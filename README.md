# vibe 知识视频工作流   : )

> 把一个知识点，做成一张会动的图，字幕和动画共用一条时间轴。

一套用来做「知识类短视频 / 科普中视频」的工程化方法：画面是**单个 HTML 文件**，动画由 `requestAnimationFrame` 驱动，字幕内嵌在同一份代码里，浏览器全屏录屏即成品。

不需要剪辑软件，不需要动画软件，不需要装任何依赖。

```
知识点 → 反差句 → 单文件 HTML → 浏览器录屏 → 发布
```

## 它解决什么问题

主流做法是「AI 生成网页 → 录屏 → 剪映加字幕/BGM」。两个隐性成本：

**字幕和动画是两条时间线。** 你想要   【第 20 个点亮的瞬间，正好浮出“占比停在 80%” 】，就得在剪映里逐帧对齐。改一次内容，重对一次。

**改不动。** 录完发现字号小了、某句断行难看、某个数字错了 —— 只能重录，连带重新对字幕。

把字幕放进 HTML，两个问题一起消失：**字幕和画面读同一个 `t`**，动画改到哪里，字幕自动跟到哪里；改文案只是改一行数组，刷新页面即可。

```
剪映模式：  画面轨 —— 独立 —— 字幕轨
本工作流：  同一份 JS 里的 CUES[] + SCENES[] → 同一个 t → 同时渲染
```

## 30 秒上手

```bash
git clone <this-repo> && cd vibe-knowledge-video

# 1. 打开一个模板，浏览器里看效果
open templates/short-60s.html        # macOS
start templates\short-60s.html       # Windows

# 2. 改文件顶部的 CONFIG 和 CUES（只有这两块需要动）
# 3. 全屏，录屏，完事
```

真实成品见 [`examples/`](examples/)：一个 24 秒短版（二八法则），一个 6 分 36 秒长版（目录学史）。

## 五条铁律

这五条是这套东西成立的全部。违反任何一条，成品就会立刻降级成屏保。

| # | 铁律                 | 为什么                            |
| - | ------------------ | ------------------------------ |
| 1 | **数字必须是你手里的真数**    | AI 只负责画，不负责编。观众第一眼就在核对数字       |
| 2 | **字幕必须内嵌在 HTML 里** | 两条时间线永远对不齐，一条就永远不会错            |
| 3 | **画面文字和字幕不能重复同一句** | 画面归书面金句与硬数据，字幕归口播白话。复读等于浪费一半屏幕 |
| 4 | **动画跑完必须落一句结论**    | 没有结论的动画叫动态壁纸                   |
| 5 | **每一帧都必须可寻址**      | 有了 `?t=秒数`，才能逐帧检查、才能返工、才敢改     |

## 两个版本，区别不在时长

|       | 短版（15–40 秒）      | 长版（5–8 分钟）            |
| ----- | ---------------- | --------------------- |
| 靠什么撑住 | 一个奇观，一次反转        | 一条叙事线，两次反转            |
| 场景数   | 1                | 6–10                  |
| 字幕    | 可选，画面自己能说清       | 必需，是主要叙事通道            |
| 难点    | 反差点够不够锋利         | 每 40 秒有没有一个新信息        |
| 模板    | `short-60s.html` | `long-narrative.html` |

判断标准：**你的知识点能不能只用一句话说完，并且这半句让人意外。** 能，做短版；不能，先老老实实写分镜。

## 工具用法

```bash
node tools/check-js.mjs    templates/long-narrative.html   # 语法 + 反模式 + 复读
node tools/check-breaks.mjs examples/02-muluxue.html       # 字幕断行是否合理
node tools/snap.mjs        examples/02-muluxue.html 30 120 280 393   # 截四帧
node tools/export-cues.mjs examples/02-muluxue.html        # 出 srt + txt
```

`check-js.mjs` 会挑出三类东西：**语法错误**、**违反工作流约束的写法**（用 `setTimeout` 驱动动画、引用外部资源、缺 `?t=` 支持）、以及**画面文字与字幕复读**。

最后一条尤其值得说：这是最隐蔽、也最伤片子的错误 —— 同一个意思在屏幕上下各出现一次，观众读两遍，等于浪费一半信息位。人眼很难逐条比对，所以我把它做成了自动检查。

`snap.mjs` 会自动找本机的 Edge / Chrome，用 `--headless` 出图。这是这套流程里最省时间的一环：**不要靠肉眼回放**，直接按时间点截帧，一眼看出哪里溢出、哪里空了半屏。

## 适合 / 不适合

**适合**：有真实数据或明确史实、能提炼出反差点、接受一张图讲一件事的知识内容。历史、经济、统计、科学、行业观察。通常而言一个视频不要讲太复杂的东西为宜。

**不适合**：需要真实影像素材的题材（纪录片式叙事）、纯观点输出（没有可可视化的对象）、连续剧情。这套方法的瓶颈从来不是技术，是**你有没有一个好反差点**。
