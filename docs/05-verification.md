# 验证：不要靠肉眼回放

人眼回放会漏掉一闪而过的排版问题 —— 内容溢出被字幕压住 0.3 秒，你根本不会注意到，但观众会截图发到评论区。

因为页面是**可寻址**的，验证可以机械化：按时间点截帧，逐张看。

## 逐帧截图

```bash
node tools/snap.mjs templates/long-narrative.html 4 20 48 120 200 284 393
```

脚本会调本机 Edge/Chrome 的 headless 模式，输出 `snap/t004.png`、`snap/t020.png`……

### 时间点怎么选

每个场景取三个点：**开头 +0.5 秒**（进场是否完成）、**中段**（动画进行到一半）、**结尾 −0.5 秒**（内容是否堆满）。

长版 10 个场景约 30 张。听起来多，实际每张看 2 秒，5 分钟能过一遍 —— 比录一条 6 分钟的视频再回放快得多。

另外**必须单独检查的几类帧**：
- 最长的那条字幕所在时刻（会不会折成三行、会不会压住内容）
- 数字最大的那一屏（大数字字号是否溢出）
- 结论页（金句折行是否出现孤字）

## 六项检查表

每张图逐项过：

| 项 | 不合格的样子 | 原因 |
|---|---|---|
| **溢出** | 内容被底部字幕压住，或超出画布下沿 | 内容高度超过 1450px 可用区 |
| **空屏** | 内容全挤在顶部，中下部大片空白 | 漏了 `justify-content:center` |
| **断行** | 「每一种 / 书」「经史子集— / —最多的」 | 断行函数没生效或漏了破折号分支 |
| **复读** | 画面大字和字幕是同一句话 | 分工没做，见 [排版](04-typography.md#画面文字与字幕的分工)。三种形态可自动检测，见下节 |
| **孤字** | 最后一行只剩 1–2 个字 | 手动 `<br>` 位置不对 |
| **比例** | 条形长度和标注数字不成正比 | 宽度值手写错了，没按数据算 |

**比例那条最隐蔽。** 3461 和 6793 的条形，如果宽度给了 448 和 880，比例是 1:1.96，而数字比是 1:1.96 —— 对得上。但如果给成 448 和 800，视觉上就差了一截，观众感觉不对但说不出哪不对，最后是"这图看着假"。

比例按最大值的百分比算：

```js
const max = Math.max(a, b);
const wa = a / max * TRACK;   // TRACK = 条形轨道总宽
const wb = b / max * TRACK;
```

## 语法检查

改完 JS 一定要跑一次：

```bash
node tools/check-js.mjs templates/long-narrative.html
```

它把 `<script>` 内容抽出来交给 `node --check`。**很多排版 bug 其实是 JS 报错导致渲染函数中途退出** —— 页面看着"只是空白了一块"，实际是控制台在报错。

同时它会跑三项静态比对，都是肉眼会漏的：

| 检查 | 抓什么 |
|---|---|
| 反模式 | `setTimeout` 驱动动画、外部资源、缺 `?t=` 时钟 |
| 复读（整句 + 短标签） | 画面「经 / 史 / 子 / 集」四张卡 + 字幕「经、史、子、集」 |
| 复读（数字） | 画面「3461 种 · 79309 卷」+ 字幕「著录 3461 种、79309 卷」 |

短标签那条按"字幕里每个字都能在画面上找到独立标签"判定，数字那条按"同一场景内出现过的数字集合"判定 —— 数字常被拆在多个标签里（`<span>596</span><i>/300</i>`），按标签比对是抓不到的。

## 字幕断行检查

```bash
node tools/check-breaks.mjs examples/02-muluxue.html
```

逐句列出每行的全角字宽、是否自动折行、是否手写 `<br>`，并标出超宽行。它算的是**字符宽度**（中文 1、西文 0.55），不是字符个数 —— 「《汉书·艺文志》，中国现存最早的图书目录」只有 20 个字，但含书名号和标点，实测 19.6 个全角宽，超过 16 就得断。

## 数据核对

发布前把每个数字和来源对一遍：

```bash
node tools/export-cues.mjs examples/02-muluxue.html --audit
```

`--audit` 会把字幕里所有数字抽出来列成一张表，方便逐条比对自己核过的原始资料。

**这条不能省。** 知识区观众的核对能力远超预期，一个错的卷数会被顶到评论区第一条。

## 三个容易误判的现象

**1. 截图是空白 / 只有一半。**
先检查是不是 `?p` 模式下没禁用 transition。

```js
if (PAUSED) document.querySelector('.stage').classList.add('nofx');
```
```css
.stage.nofx *{ transition:none !important; }
```

CSS 过渡跟 `t` 无关，跳到某帧后属性会从当前值慢慢过渡过去，截到的是中间态。

**2. headless 截图失败 / 输出 0 字节。**
多半是**文件路径含中文**。Windows 下 headless 对非 ASCII 路径经常静默失败。`snap.mjs` 已处理：先复制到系统临时目录再截。

**3. 某一帧字体和别的不一样。**
用了外部字体（Google Fonts / 可变字重 CDN）。headless 没有网络，回退到系统字体。**必须用系统字体栈**：

```css
font-family:"PingFang SC","Hiragino Sans GB","Microsoft YaHei","Noto Sans SC",system-ui,sans-serif;
```

这条也是"单文件、零外部依赖"的另一个理由。

## 录制前的最后三件事

1. 全屏，确认画面两侧无黑边（`fit()` 会等比缩放，超宽屏两侧留黑是正常的，录屏时裁掉即可）
2. 按 `H` 隐藏右下角提示，或网址加 `?clean`
3. 刷新一次页面，从头录 —— 不要从 `?t=` 开始，`base` 会有偏移
