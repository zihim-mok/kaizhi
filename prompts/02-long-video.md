# 长版提示词（5–8 分钟）

短版靠一个奇观，长版靠一条叙事线。**不要一次让 AI 生成 1000 行代码** —— 先分镜，再代码，中间有一个人工审核点。

```
阶段 A：核数据 → 出分镜表 + 字幕稿 → 你审 → 阶段 B：生成代码 → 逐帧验证
```

---

## 阶段 0：核数据（事实类题材必做）

历史、统计、行业数据类题材，先让 AI 把数字查清楚，**再动笔写分镜**。顺序反了会返工。

```
我要做一期关于「{{中国古代目录学}}」的科普视频，需要你先把关键史实和数字核准。

请查证并给出确切数值，每一条都要说明出处（书名/篇名）：
1. {{《汉书·艺文志》的分类层级、家数、卷数}}
2. {{《隋书·经籍志》的四部分类、部数、卷数，以及经部和史部各自的部数卷数}}
3. {{《四库全书总目》的著录种数卷数、存目种数卷数}}
4. {{章学诚《校雠通义》的成书年份、"辨章学术考镜源流"的出处、互著与别裁的定义}}
5. {{刘向校书的年份、《别录》的卷数、刘歆《七略》的七个部分}}

要求：
- 只给能查到的确切数字，查不到的直接说"未查到确切值"，不要估算、不要四舍五入
- 如果不同来源的数字有冲突，把冲突列出来
- 最后单独列一栏：哪些数字你没能确认
```

**这一步的产出决定了哪些内容能写、哪些必须留白。** 目录学那期最终没给子部和集部的卷数，因为查不到确切值 —— 卡片上只放类数，宁可空着。

---

## 阶段 A：出分镜

拿到核实过的数据后，再让 AI 出分镜。**这一步不要让 AI 写代码。**

```
我要做一期 6–8 分钟的竖屏知识科普视频，讲「{{目录学}}」，请先出分镜，不要写代码。

我已经核实过的数据（只能用这些，不要引入新数字）：
{{粘贴阶段 0 的结果}}

叙事要求：
- 开头 6 秒是钩子：不讲"XX 是什么"，直接抛一个反常识的事实，这 6 秒不放字幕，只有两行大字
- 结构要有两次反转：第一次建立意义，第二次推翻第一次的结论
- 每 40 秒内必须有一个新信息点，否则观众会走
- 信息密度最高、情绪最强的那一段放在全片 2/3 处，不要放结尾
- 结尾用一句话收束，不放新信息

请输出三张表：

表一 场景表（总数 8–10 个）
| 序号 | 起止秒 | 时长 | 这一屏讲什么 | 画面做什么 | 视觉形式（点阵/条形/时间轴/节点链） |

表二 字幕稿
| 序号 | 起止秒 | 字幕文本（8–16 字） | 画面上的文字（必须和字幕不同） |

表三 数据核对表
| 画面出现的数字 | 数值 | 出处 |

约束：
- 字幕和画面文字不允许有任何一句完全相同
- 总时长控制在 380–420 秒
- 场景时间必须首尾相接，最后一场结束时间 = 总时长
- 表二里每一行都要落在表一的某个场景区间内，我会核对
```

**审核重点**（这三条不过就别进下一步）：

1. **场景时间是否首尾相接** —— AI 经常留缝或重叠
2. **字幕有没有和画面文字重复** —— 逐条比对，重复的删一个
3. **数据核对表是否完整** —— 每个数字都要有出处

## 阶段 B：生成代码

拿着确认过的分镜表生成。这个提示词比较长，但**一次给全比反复补要求快**。

```
根据上面的分镜表和字幕稿，生成一个单独的 HTML 文件（不引用任何外部资源）。

【整体】
- 画布固定 1080×1920，等比缩放居中
- 深色背景（近黑 + 极淡径向渐变），主色只用一种暖金，其余灰阶
- 系统字体栈："PingFang SC","Hiragino Sans GB","Microsoft YaHei","Noto Sans SC",system-ui,sans-serif
- 每个场景是一个 <section class="scene" data-s="N">，绝对定位铺满画布，默认 opacity:0，加 .on 时显示
- 场景内容必须垂直居中（flex + justify-content:center），底部留 340px 给字幕，绝不能全挤在顶部

【代码结构（重要）】
1. 顶部三个数据块，内容和样式严格分离：
   const TOTAL = 400;
   const SCENES = [{ s:0, t0:0, t1:6 }, ...];
   const CUES = [[起始秒, 结束秒, '文本'], ...];
   其余是工具函数和 render()。

2. 所有动画必须是 render(t) 的纯函数输出 —— 同一个 t 渲染出同一个画面。
   - 禁止 setTimeout / setInterval 驱动动画
   - 禁止累积状态（比如 "已经亮了几个" 这种计数器）
   - 每一帧都从 t 直接算出每个元素的当前状态，例如：
     const on = t >= litAt[i];
     el.classList.toggle('lit', on);
   - 主时钟用 performance.now()，不要用帧计数

3. 提供进度映射工具：
   const pr = (t,a,b) => clamp((t-a)/(b-a), 0, 1);
   所有渐变动画（宽度、透明度、位移）都写成 easeOut(pr(t, 开始, 结束)) 的形式

4. 只在值变化时写 DOM，避免每帧重排：
   function set(id, prop, val){ const el = $(id); if(el.__k !== val){ el.__k = val; el.style[prop] = val; } }

5. 网址参数：
   ?t=秒数      从该秒开始播放
   ?t=秒数&p    停在该帧，并且给根元素加 .nofx 禁用所有 CSS transition
                （否则截图会截到过渡中间态）
   ?clean       隐藏右下角快捷键提示
   快捷键：空格重播、← → 快退快进 10 秒、F 全屏、H 切换提示

【字幕】
- CUES 驱动，和动画读同一个 t，一句话一屏
- 字号 56px，字重 600，行高 1.5，居中，带 text-shadow: 0 2px 24px rgba(0,0,0,.9)
- 内置断行函数：超过 16 个全角字时自动断成两行，只在标点（，、：。？！；）之后断，
  断点取最接近视觉中点的那个；破折号 —— 不能被拆到两行；句子里已有 <br> 时尊重手写换行
- 淡入 0.34 秒，淡出 0.28 秒，用 pr() 算，不要用 CSS transition

【视觉细节】
- 数字用 tabular-nums，大数字要敢给大（90–130px）
- 结论出现时把背景压暗（opacity 0.2 左右），让视线全部交给那句话
- 条形图/进度条的宽度必须按数据比例算，不能手写数值：
  const w = value / max * TRACK_WIDTH;
- 中文标点用弯引号 “”，不要用直角引号 「」

生成后请告诉我：
1) 每个场景的起止秒和对应内容
2) 哪个数字是算出来的、怎么算的
3) 建议我先看哪几个时间点来验证画面（挑最容易溢出的那几帧）
```

## 长版特有的四个坑

**场景时间留缝。** `{s:0,t0:0,t1:6}` `{s:1,t0:6.2,...}` —— 6.0 到 6.2 之间是空屏。生成后逐项检查 `t1 === next.t0`。

**字幕跨场景。** 某句字幕从 105.4 到 110.2，跨过了 106 秒的场景边界，导致前半句留在上一屏。写稿时每句都要落在同一场景内。

**每屏都想塞满。** 长版的节奏靠留白，不靠信息密度。目录学那期 S8 有 11 秒完全没字幕，让画面那句话自己站住 —— 这是全片效果最好的一段。

**字幕写太满。** 6 分半按 260 字/分钟算，上限 1700 字。实际用了约 1000 字（71 句 × 14 字），留出了停顿。写满会让观众累。
